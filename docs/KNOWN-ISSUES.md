# 已知问题与设计说明

本文件记录**有意保留**的设计决策与低影响问题。此前记录的行为怪癖已在
2026-08 的重构中按合理逻辑修复（见 [CHANGELOG.md](CHANGELOG.md)），此处仅保留
属于设计意图或不值得修复的条目。

## 设计意图（不是 bug）

1. **总结缓存随新消息失效**：缓存键包含最新消息时间戳，群里有任何新消息后旧缓存即失效——保证总结时效性。

2. **多重频控各司其职**：全局 10 次/分钟每用户限流（防刷）、3 秒 `/summary` 节流（防手抖重复）、5 分钟每用户每群冷却（控 AI 成本）三者叠加生效；任务失败会自动退还冷却。

3. **管理员未配置时 `/status` 与 `/admin` 拒绝所有人**：安全默认，首次访问时记录警告（`ADMIN_USER_IDS`）。

4. **bot 界面文案固定为简体中文**：`formatSummaryResponse` 的"群组聊天总结/分析统计"等外层标签不随检测语言变化；AI 生成的正文与分节标题（含繁体 zh-tw）跟随群组语言。

5. **消息入库不做内容改写**：用户名等数据原样存储，Markdown 冲突由显示侧 `escapeMarkdown` 与 AI 提示词侧 `makeSafeUserName` 处理。

## 低影响已知问题

- **`truncateToTokenLimit` 的 token 估算是粗略启发式**（约 2 字符 = 1 token，实际按 1.8 系数截断尾部），中文场景偏保守，不影响正确性。
- **`getRecentMessages` 取 `LIMIT` 条后一次性载入内存**：当前上限 1000 条，可接受。
- **`detectLanguage` 为字符计数启发式**：繁简区分基于 54 对专用字符的计数对比，极端混合文本（如繁简各半）可能判为繁体。
- **`finish_reason: 'length'` 只记录不重试**：输出被截断时依赖 JSON 修复链兜底，属于既有的成本取舍。
